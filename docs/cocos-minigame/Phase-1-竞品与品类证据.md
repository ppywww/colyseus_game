### 1.3 竞品层三条硬观察

**观察 1｜单局时长是本次拆解中最大的公开数据空白，但两侧锚点都指向"短"。**【实证·官方 + 参考·未核实 → 推断】
五款竞品的单局时长**全部未核实**，说明行业不把它当对外卖点 / 或数据不公开。但两侧锚点很明确：官方榜单给《使命召唤手游》的文案是「**五分钟一局**」【实证·官方】，一个外包商 4v4 射击小程序方案写的是「3 分钟快节奏对战」「15 秒未凑齐 4v4 自动填 Bot，**20 秒内必开局**」【参考·未核实，仅作行业做法参照】。
→ **【推断】** 本项目现状「90 秒/回合 × 最多 5 回合 = 最长 450 秒 ≈ 7.5 分钟」，加回合间隔、结算、匹配等待后单局可能 8–10 分钟，**明显长于品类锚点**。这是立项阶段最该先修的差距项，且是纯设计改动、不依赖引擎。

**观察 2｜射击榜头部被「正版 IP + 大厂 App 轻量化」占据，白身新品挤的是"卡通 / 萌系 / 爽点"侧翼。**【实证·官方 → 推断】
TOP10 里《使命召唤手游》（文案明写「正版IP授权」）、《穿越火线-枪战王者》、《逆战:未来》均为大厂 IP；而非 IP 产品靠的是「Q版激萌」「小鸭子」「修勾」这类**低门槛卡通符号**。
→ **【推断】** 本项目「现代高饱和卡通 + 玩具武器」的方向与侧翼打法吻合，是可保留资产；但「猫鼠」题材会直接撞上已有官方授权产品（见 §4.1），**必须先做原创化才能谈差异化**。

**观察 3｜五款里有四款把"局外养成"写进了核心循环，纯对局产品几乎不单独存在。**【实证·官方/媒体 → 推断】
A 枪支合成/SSS 装备、B 武器经验卡/天赋/季票、C 金币商城、D 武器合成/地图解锁——只有 E 因资料不足看不出。这与平台侧「IAA 走向混变」的趋势互证（见 §3.4）。
→ **【推断】** 本项目目前是「纯对局 + 结算」结构，**缺失局外成长层**，而局外成长正是激励视频最自然的挂载位。不补这一层，IAA 点位会少掉一半。

## 3. 商业轴 C 验证（四条逐条给结论）

> 结论用词固定为「可行 / 有条件可行 / 不可行」，每条附理由与证据等级。

### 3.1 【有条件可行】4v4 实时联机 + 服务端权威在微信小游戏

**结论：技术上可行、制度上有前置、商业上有成本与在线池两道硬约束；四个前置条件缺一即应改为异步 PvP / Bot 对抗。**

**① wss 域名备案 —— 硬性前置，不是代码问题【实证·官方】**
微信开放文档《网络》<https://developers.weixin.qq.com/minigame/dev/guide/base-ability/network> 明确：域名只支持 `https` / `wss`；**域名必须经过 ICP 备案**；不能用 IP 或 localhost；不支持父域名、须用子域名；`wss` 域名无需配置端口（默认允许该域名下所有端口）；TLS 须 ≥1.2，证书链须完整。开发期可在开发者工具勾选「不校验合法域名」绕过，**但正式上线版本必须配置**，Unity 适配文档亦重申「上线版本的网络请求必须配置安全域名」。
→ **动作**：把「已备案域名 + 有效 SSL 证书 + TLS1.2」列为提审前置 P0。若用**微信云托管**，官方文档给出例外：通过 `callContainer` / `connectContainer` 走微信私有协议，**可无需配置通讯域名**——这对本项目现成的 Colyseus 服务端迁移是一个值得评估的降本路径【实证·官方，但是否适配 Colyseus 需工程验证】。

**② 冷启动匹配人数 —— 8 人同房间是最大的商业风险【实证·媒体 + 推断】**
腾讯云 MGOBE 官方文档直言：「**游戏刚上线时，玩家数量不多，可能无法为每一个玩家匹配到真人对手，那么此时就可以匹配机器人玩家**」，并把「场景匹配算法复杂 / 冷启动阶段用户不足导致匹配时间过长劝退」列为联机小游戏第一道坎；华为联机对战服务同样提供「匹配不足时**自动填充机器人**，避免超时导致匹配失败」及「掉线重连时间」配置，且明确支持微信小游戏平台。一个外包 4v4 方案写的是「15 秒未凑齐 4v4 自动填 Bot、20 秒内必开局、单房间最大 8 人」【参考·未核实，仅说明行业做法】。
→ **【推断】** 本项目要求 8 个真人同时在线才能开一局，且 4v4 战术竞技对"缺 1 人"极敏感（少一人即阵型崩）。**必须做 Bot 填充，且 Bot 要能撑满 7 个位置并具备基本战术行为**，而不是只补 1–2 个。上线初期应默认「1 真人 + 7 Bot」，随 DAU 增长渐次替换真人。

**③ 同时在线成本 —— 状态同步房间服是有状态服务，成本非线性【实证·媒体 + 推断】**
腾讯云 MGOBE 指出：「对战游戏通常一个对局的玩家要连接到同一台服务器上，这样基础云产品提供的负载均衡、弹性扩缩容就会**失灵**，导致运维成本增加」，并把「就近接入 / 负载 / 弹性扩缩容」形容为小团队至少半年的后端「大山」。本项目 Colyseus 0.16 **服务端权威**正是标准的状态同步架构（伤害/命中在服务端判定），恰好落在这一类。
→ **【推断】** 4v4 小房间意味着「8 个用户占一个房间实例」，单位用户服务器成本显著高于无状态 HTTP 小游戏；且冷启动期大量房间是「1 真人 + 7 Bot」，**等于用真服务器成本跑单机体验**。**具体金额/单价未核实，本文不编造任何数字**；立项时应单独列一项「房间服成本模型（按峰值房间数而非按 DAU 估）」，并评估用 Bot 局走本地/端侧结算、真人局才上房间服的降本方案。

**④ 断线重连 —— 平台会主动切断，不是可选优化【实证·官方】**
微信《网络》文档：「小游戏进入后台运行后，如果 **5s 内网络请求没有结束**，会回调 `fail interrupted`；在回到前台之前，网络请求接口调用都会无法调用」；`wx.connectSocket` 最大并发 **5**，`wx.request` 系列最大并发 **10**，网络超时默认/最大 **60s**。
→ **【推断】** 微信生态里"切消息 / 锁屏 / 来电"极频繁，4v4 中任一玩家切后台即掉线，若不处理会直接毁掉另外 7 人的一局。**必须做：断线即由 Bot 接管角色 + 前台恢复后重连回原房间 + 掉线宽限期**。华为服务把「玩家掉线重连时间」做成可配置项，说明这是联机对战服务的标准能力而非特色功能。

**⑤ 叠加约束：未成年人在线池几乎为空【实证·官方 → 推断】**
国家新闻出版署 国新出发〔2021〕14 号（2021-09-01 施行）：所有网络游戏企业**仅可在周五、周六、周日和法定节假日每日 20 时至 21 时**向未成年人提供 1 小时服务；必须接入 NPPA 防沉迷实名验证系统；**不得以任何形式（含游客体验模式）向未实名注册和登录的用户提供游戏服务**【实证·官方 <https://www.nppa.gov.cn/xxfb/tzgs/202108/t20210830_666285.html>】。
→ **【推断】** 实时匹配的可用真人池在工作日白天基本不含未成年人，冷启动匹配难度进一步上升，且**不能靠"游客模式先玩"绕过**（法规明文禁止）。这是"必须 Bot 填充"的第二个独立理由。

> **汇总判定**：满足 ①已备案 wss 域名 ②Bot 填充 + 真人渐替 ③断线重连 + Bot 接管 ④房间服成本模型先算清 → **有条件可行**；任一不满足 → 建议把 PvP 降为「异步战绩对战 / Bot 对抗」（《开局一条枪》的 PVP 即为按阵容战力模拟的异步对战【参考·未核实】），这能同时砍掉 ②③④ 三项成本。

### 3.2 【有条件可行，但当前选型明显偏离主流，建议靠拢】竖屏 750×1334 + 触屏第一人称射击

**结论：可行的是「竖屏 + 自动开火/强辅助瞄准 + 视角可切」；不可行的是「竖屏 + 纯手动第一人称精准射击 + 8 人实时对抗」。**

**① 已验证产品的做法【实证·媒体】**
- **B 迷你枪战精英**：双摇杆（左移动 / 右开火）、一键开镜开火 / 腰射 / **自动开火**（开启后开火键消失，准心对准敌人即自动射击）、**自动瞄准**、压感射击辅助、**可开陀螺仪辅助**、自定义按键位置与大小、水平/垂直灵敏度可调【百度百科 + 历趣网】。这是本次调研里**最完整、最可直接抄的触屏射击操作基线**。
- **C 混乱大枪战**：横屏、左手移动+方向、右手开火/攀爬/跳跃，**支持第一人称与第三人称视角切换**，敌方头顶骷髅标志区分敌我、友军不损血【凤凰网】。注意：唯一可查证的 4V4 实时 PVP 案例是**横屏**。
- **A 全民枪神边境王者**：含**自瞄机制与人机试炼**等新手友好设计【18183】。

**② 竖屏射击的通行解法（来源可信度较低，仅用于归纳方向，不作实证）【参考·未核实】**
| 范式 | 操作 | 出处 | 是否为自由移动 FPS |
| --- | --- | --- | --- |
| 自动锁定 + 自动开火 | 虚拟摇杆走位，枪械自动锁定最近敌人开火，手动点击可切换目标；自动瞄准 + 滑动走位 | 《开局一条枪》18183 下载页 | 否（俯视/半自动） |
| 滑屏找物 + 点击开镜 | 滑动屏幕调整观察视角，点击切狙击镜，瞄准后点开火；**竖屏第一人称、单指完成所有操作** | 《狙击外星人》17xy 下载页 | 否（定点狙击） |
| 自动前进 + 拖动横移 | 按住屏幕左右拖动控制小队横向移动，**小队自动朝前方开火** | Cocos Store《Last War Like》【实证·社区/官方商城】 | 否（跑酷射击） |
| 竖屏 FPS 双摇杆 | 触屏移动+瞄准、陀螺仪可选、单手刚枪、3–5 分钟一局 | 《突击枪王特工》17yoo 页 | 声称是，但**同页操作说明又变成"键盘方向键+鼠标点击"，描述自相矛盾，疑似 AI 生成，不采信** |

→ **【推断】关键发现**：在本次可查证范围内，**找不到一款「竖屏 + 自由移动 + 手动瞄准 + 4v4 实时 PvP」的成功产品**。竖屏射击的共性是把"瞄准"这一操作负担彻底删掉（自动锁定 / 自动开火 / 定点开镜），只保留"走位"或"选择"。而真人对抗 FPS 的可查案例选择了横屏。这说明本项目「竖屏 + 纯第一人称手动瞄准」不是"还没人做过的蓝海"，而是**与品类已验证解法相逆的选型**。

**③ 竖屏 750×1334 的具体工程约束**
- 横向视野窄，第一人称的水平瞄准余量小，8 个高速移动目标容易出画【推断】；
- 双摇杆在竖屏会挤占下半屏，且左右手多点触控必须跟踪 `touch id`，否则「左手移动时右手点开火导致移动停止」【参考·未核实 个人实战博客】；按钮热区建议 ≥44×44px【同上，未核实】；
- 必须避让刘海与**右上角小游戏胶囊按钮**：`wx.getSystemInfoSync().safeArea`【实证·官方 API】；Cocos Store《Last War Like》明确「顶部 UI 会避开刘海和小游戏的胶囊按钮」【实证·社区】。

**④ 建议操作方案（四选一，按推荐度排序）**

| 方案 | 内容 | 判定 |
| --- | --- | --- |
| **A（推荐）** | 左虚拟摇杆移动 + 右半屏滑动转向 + **默认自动开火 + 强辅助瞄准**；陀螺仪做可选微调开关；保留第三人称/越肩视角切换 | 最靠拢品类惯例，直接复用 B 的已验证方案 + C 的视角切换 |
| B | A + 陀螺仪作为主瞄准 | **不推荐单独使用**：B 把陀螺仪定位为"辅助"而非主输入，且竖屏举机瞄准疲劳度高【推断】 |
| C | 改为第三人称/越肩为主视角 | 可缓解竖屏视野窄；C 已验证可切换【实证·媒体】；但会削弱"第一人称 FPS"的原有资产 |
| D | 保持纯手动双摇杆 FPS | **不推荐**：竖屏 + 8 人实时 + 手动瞄准 = 操作负担叠加，与"轻操作"硬背景冲突 |

> **汇总判定**：**有条件可行**。允许条件 = 采用方案 A（或 A+C）、把"瞄准"从玩家职责里移除、并完成竖屏多点触控与安全区适配。若坚持 D，则本条应改判为**不可行**（无已验证先例 + 操作负担超标 + 首 30 秒零门槛无法满足）。

### 3.3 【有条件可行，且是四条里工程风险最高的一条】Cocos Creator 3.8.x 做 3D 第一人称射击的性能边界

**结论：8 人同屏不是做不出来，但必须同时满足 5 个工程条件；且现有正面案例不能等价外推到「8 个真人网络实体」。**

| 全部主包+分包合计 | ≤ **30M** | ≤ **20M**；开通虚拟支付后 ≤ 30M |
| 分包数量 | 官方文档未写 | 实际限制 **≤100 个**（社区经验） |

> 来源：微信开放文档 <https://developers.weixin.qq.com/minigame/dev/guide/base-ability/subPackage/useSubPackage.html>【实证·官方】；Cocos 中文社区 XForge 分包最佳实践 <https://forum.cocos.org/t/topic/156906> 与 Gitee 镜像【实证·社区】。**两个总量口径不一致，本文不擅自取舍，以提审当日 mp 后台实际校验为准。**

**② 3D 引擎自身就吃掉大半主包【实证·社区】**
Cocos 社区实测（3.8.2）：**3D 游戏在不启用物理引擎的情况下，引擎基础资源约 3M**（2D 全功能约 2.5M），因此「开发 3D 游戏主包仅剩 1M 左右」的业务空间。
→ **【推断】** 本项目（3.8.8、3D、多角色多武器）**几乎必然**需要：构建时「主包压缩类型」选「小游戏分包」+ Asset Bundle 拆分（脚本→小游戏分包、贴图/音频→远程分包）+ **部署远程资源服务器**。这不是优化项，是启动前提。可用 `wx.loadSubpackage` / `wx.preDownloadSubpackage`（基础库 3.4.9+）做按需与预取【实证·官方】。

**③ 正面案例：与本项目同引擎同版本的竖屏 3D 射击【实证·社区 / 官方商城】**
Cocos Store 资源《Last War Like》<https://store.cocos.com/dashboard/detail/9771>：**Cocos Creator 3.8.8**（与本项目目标版本完全一致）、TypeScript、**Legacy Forward 渲染管线（页面明确写"为移动端性能选择"）**、竖屏 3D 玩具兵射击、已适配微信小游戏。作者自述性能方案与结果：
- GPU instanced skinning + LOD + frozen instances → **百人军团同屏稳定 60 帧**；敌人模型亦用 LOD；
- 动态分辨率（GPU 瓶颈时自动降渲染分辨率，稳定后回升并记忆设备档位）；
- 加载期 shader 预热队列防首次入关卡顿；音频通道固定池避免频繁创建原生音频实例；
- 内置性能 HUD（帧率 / JS 耗时 / DrawCall / 三角面数 / 渲染分辨率）；
- 包体策略：**初始包只含加载屏**，游戏逻辑与模型放 game bundle，音频后台加载，第 2 关起的场景与模型远程按需下载、当前关预取下一关；
- IAA 点位齐全（每日奖励 / 看视频领金币 / 结算页看视频金币翻倍 / 商店看视频领宝石）。

> **重要限定（不可外推）**：这是**商城模板资源、非上线产品**，帧率为作者自述、非受控验证；「百人」是 GPU 实例化的无网络实体士兵，**不等于 8 个真人玩家的骨骼动画 + 网络状态同步 + 服务端权威判定**。该案例能证明的是「3.8.8 + 竖屏 3D + Legacy Forward + 实例化」这条技术路线跑得通，**不能证明 8 人实时 PvP 能跑满帧**。

**④ 反面案例：多个 3D 角色同屏在 iOS 低端机是明确帧率悬崖【实证·社区】**
Cocos 中文社区实测帖《高手请进，微信小游戏 iOS 性能优化探讨》（3.8.0，2023）<https://forum.cocos.org/t/topic/153231>：安卓机 50–60fps 正常；**iPhone X 仅 20–30fps**；开启微信高性能模式后 iPhone X「画面显示自己控制的 3D 角色时稳定 60，**一旦显示其他 3D 角色就骤降到 10–20fps**」；iPad 8 有锁 30fps 现象；iPhone 11 / 14 不卡。
→ **【推断】** 「看见其他 3D 角色就掉帧」正是 8 人同屏 FPS 的核心失效模式。这是个案、非受控实验，但来自引擎官方社区且与 ③ 的作者要用 LOD/实例化/动态分辨率的原因互相印证，**应作为立项风险而非噪声处理**。

**⑤ 工程验收阈值参考（非官方标准）【参考·未核实】**
一份第三方 Cocos 小游戏上线 checklist（eastondev.com，2026-05）给的经验值：高端 ≥55fps / 低端 ≥28fps、低端内存峰值 ≤700MB、DrawCall 首屏 ≤100 / 局内 ≤200、首屏加载 ≤3000ms、主包建议 ≤3.8MB、总包建议 ≤15MB；并把「主包 >4MB、卡顿严重」列入驳回 Top5。**此为第三方经验值，不是微信官方标准，仅用作内部验收参考，不作为对外承诺。** 另有个人博客声称「Cocos 3.8.0 是 Production Ready for Mini Games 的 LTS」「同场景比 Unity 高 12fps / 内存低 37%」【参考·未核实，数字无来源，本文不采信】。

> **汇总判定**：**有条件可行**，但必须满足 ①用 Legacy Forward 而非新管线 ②角色 LOD / 实例化 / 降级档位 ③首包仅加载屏 + 远程分包 + 预取 ④低端 iOS 真机（iPhone X 档）验收 8 人同屏 ⑤掉帧自动降画质兜底。**建议把「8 人同屏真机性能 spike」排在所有玩法开发之前**——若这一条不过，§3.1 的联机架构投入会全部沉没。

### 3.4 【可行，但纯 IAA 天花板明确】IAA 激励视频为主的变现路线

**结论：纯 IAA 是本项目最快、最合规的上架路径（免版号），但当前「纯对局 + 结算」结构广告位≈0，必须先补局外养成层；且 PvP 公平性划出一条不可越的红线。**

**① 可挂点位逐条（结合本项目已有结构）**

| # | 点位 | 具体设计 | 已验证参照 | 对本项目改造量 |

**② PvP 公平性红线（本条为【推断】，但是变现设计最该守住的一条）**
在**真人 4v4 实时对局**里用激励视频换数值优势（伤害 / 弹药 / 复活 / 额外武器），会同时踩两个雷：竞技公平被破坏 → 留存受损；以及「诱导看广告 / 诱导付费」的审核风险（微信常见拒绝情形 3.2.8.9 对随机抽取虚拟道具诱导投入法定货币有明确限制【实证·官方】，3.2.8.10 对妨害未成年人身心健康内容有禁止条款）。
→ **动作建议**：IAA 收益**只作用于局外与结算**（货币、装扮、加速养成、翻倍领取），**局内只给外观与表演性内容，不给战力**。真人局与 Bot 局采用两套广告规则。

  - **IAP（内购）= 版号 + 软著，缺一不可**；
  - **IAA（广告）= 不要求版号**；软著仅在 3 种情形下需要（游戏名含英文、含「软件」字样、涉及品牌或公众人物合作）；
  - 但「免版号」≠「零门槛」：**所有小游戏发布前必须完成 ①微信认证（企业或个体工商户，游戏类目不支持个人主体）②ICP 备案**（依据《反电信网络诈骗法》第 23 条）；IAA 流程约 10–30 个工作日，工信部短信核验须 24 小时内完成。

- **【冲突 / 不采信】** 部分代办服务商文章互相矛盾：一篇称「2025 年 7 月起无版号小游戏不得上线内购，仅可广告变现；已有小游戏需在 2025 年 9 月前补办版号」，另一篇称「涉及内购**或广告变现**也必须申请版号」；另有二手报告称「2026 年新政：无版号内购小游戏一经发现立即下架，3 个月内不得重新提交审核」。这些来源多为资质代办营销内容、且与微信官方文档转述冲突，**本文不采信为结论**。
- **【动作】**：以**提审当日 mp 后台「资质审核」页**为准；立项期把「企业主体 + 微信认证 + ICP 备案 + 软著」列为不可省的前置（软著周期较长，建议与美术原创化同步启动，它同时也是 §4.1 的维权证据）。版号审批周期各方说法从 30–50 工作日到 3–6 个月不等【参考·未核实，互相矛盾】，**不写入排期依据**。

> **汇总判定**：**可行**。首发走纯 IAA（免版号、企业主体 + ICP 备案 + 软著即可），是最快上架路径；但需先补局外养成层（点位 1/3）、改造结算页（点位 1/4）、并守住「局内不给战力」红线。混变 / 内购需版号，应列为 Phase 2 目标而非首发目标。

## 4. 合规专项（明确结论）

### 4.1 【构成硬阻断：必须原创化改造】卡通猫鼠致敬形象

**结论：现有《猫和老鼠》致敬稿不能进入提审包，属于上架硬阻断，不是"上线前改一改"的打磨项。**

**证据链**
1. **【实证·媒体，转述微信官方公告】** 微信小游戏平台曾明确三类侵权及处罚：①名称侵权 → 立即清除名称；②**直接抄袭享有著作权的美术素材 → 直接下架**；③**过度借鉴美术资源 → 列为涉嫌部分素材侵权，需及时整改**（游戏茶馆 / 网易 <https://www.163.com/dy/article/DSQK0AKR052688NB.html>）。「致敬稿」至少落入第 ③ 类，若角色造型高度贴近则落入第 ② 类。
2. **【实证·媒体，转述平台运营规范】** 《微信小程序平台运营规范》：「不得提交与小游戏后台开发模板相似度过高的小游戏，**不得提交涉嫌抄袭已有游戏产品的小游戏**；不得通过简单修改游戏美术设计、视觉效果、UI、元素、素材等方式提供多个玩法、内容、功能等基本一致的小游戏」（中国青年网 2024 <https://youxi.youth.cn/yw/202409/t20240909_15505233.htm>）。
3. **【实证·媒体，法律意见】** 律师观点：游戏著作权侵权比对「**具体表达形式，包括美术风格、角色形象设计、场景画面**」，高度相似可能构成抄袭；单纯玩法相似一般难以认定侵权，但若玩法规则细化到核心机制、游戏流程、目标设定显著相似，也可能构成侵权（同上，中国青年网）。
4. **【实证·官方（该 IP 授权产品官网）】风险叠加事实**：《猫和老鼠》在中国**已有在营官方授权手游**——网易《猫和老鼠官方手游》<http://tom.163.com/>，官网明示「本游戏改编自经典动画《猫和老鼠》」、含「**5V5 团队奶酪赛**」玩法、适龄提示 8+。
   → **【推断】** 本项目「猫鼠战场 + 4v4 团队对抗 + 卡通猫鼠角色」在**题材符号、角色形象、对抗结构**三个层面同时与该授权产品接近，风险远高于抽象的"致敬"讨论；且"猫鼠"命名本身还可能触发第 1 类名称侵权。
5. **【实证·官方】** 微信《常见拒绝情形》3.2.8.12：不得误导暗示腾讯公司与该小程序有合作 / 背书关系 → 宣发素材里也不得蹭 IP 或平台背书。
6. **【参考·未核实】** 第三方 checklist 把「版权名称不符」列为审核驳回 Top5 之一。

**原创化改造的具体可改项（不是"换个颜色"）**

| 项 | 要求 |
| --- | --- |
| 角色 | 不使用汤姆 / 杰瑞的**轮廓、配色比例、五官比例、标志性姿势**；改为原创物种或原创玩具拟人（如"厨房小队"），只保留「体型差 + 追逐感」这一**玩法功能**，不保留视觉符号 |
| 名称 | 产品名、素材名、软著登记名三者一致；避开「猫和老鼠」「汤姆」「杰瑞」及近似蹭词 |
| 场景 | 厨房三通道、三路线结构属通用场景，可保留；避免复刻特定动画构图与标志性道具造型 |
| 证据 | 留存原创设计过程稿 + 申请**软件著作权登记证书**，既是版权维权核心证据，也是 IAP/软著资质前置（切游网转述微信官方文档【实证·官方转述】） |
| 流程 | **在美术立项阶段一次性做完**，不要留到提审前补丁——平台对「过度借鉴」的处理是责令整改，返工成本高于一次做对【推断】 |

### 4.2 【不构成硬阻断，但有三项必做】PvP 对抗 / 射击内容 / 未成年人防沉迷实名

**结论：射击玩法与 PvP 对抗本身不被禁止（官方射击榜 TOP10 即为反证）；风险集中在「受击表现」「陌生人社交」「实名与防沉迷」三处。**

**① 射击与暴力表现【实证·官方 + 参考·未核实】**
- 微信《常见拒绝情形》3.2.8.8：不得包含「展示**人或动物被杀戮、致残、枪击、针刺或其他伤害的真实图片**」，或宣扬暴力血腥内容；3.2.8.10 不得含妨害未成年人身心健康的内容；3.3.1 必须是完成品、不可为测试版；3.3.3 崩溃 / 卡顿严重将被拒绝。<https://developers.weixin.qq.com/minigame/product/reject.html>
- 外包商技术文归纳的审核尺度【参考·未核实，方向与官方条款一致】：目标为人类角色且击中后流血 / 断肢等写实表现大概率驳回；改为非人形对象或把受击反馈处理为**闪光、碎裂、消失**等非写实效果可正常过审；休闲射击最易过审，卡通人形目标中等敏感，写实战争 / 拟真 FPS 高敏感。
- → **【推断】本项目是天然优势项**：6 槽位玩具武器（水枪 / 橡皮筋 / 餐叉 / 平底锅 / 胡椒瓶 / 面粉袋）+ 高饱和卡通 + 非写实受击（水花 / 面粉雾 / 星星 / 弹开），正好落在最宽松一档。**这条应写进立项书作为"最该保留的资产"；不加入写实弹道、血雾与拟真后坐力，此类写实化改动会削弱上述合规优势**（部分竖屏 FPS 聚合页宣传「血雾反馈」「真实后坐力」，恰恰与审核建议相反）。

**② 适龄提示与陌生人社交【实证·官方】**
微信《小游戏适龄提示设置指引》<https://developers.weixin.qq.com/minigame/introduction/guide/slts.html>：依据《未成年人网络保护条例》《未成年人保护法》《防止未成年人沉迷网络游戏的通知》《网络游戏适龄提示》团体标准；**开发者设置后需提交平台审核，审核通过后平台统一在启动页展示**。
- **8+**：画面简约卡通手绘；竞技和对抗「以**非写实**的形式出现，不会与现实生活相混淆」；无基于文字/语音/图片的陌生人社交系统（可存在简单好友系统）；无基于历史和现实事件的改编。
- **12+**：可存在「**以对抗为主的竞技比赛**」；可存在基于文字/语音/图片自由交流的陌生人社交系统（管理须遵循法规）；画面卡通动漫手绘、无写实。
- **16+**：画面为 3D 写实或近写实风格。
→ **【推断 + 动作】** 纯卡通 + 玩具武器 + 无陌生人社交 → 可申报 **8+**；但只要做「陌生人实时匹配 + 语音/文字 + 好友排行榜」，就应主动按 **12+** 申报，并同步补齐微信《常见拒绝情形》3.2.11 要求的「过滤不当内容的措施」——即**敏感词过滤 + 举报入口 + 内容自审**。此外 3.2.8.9 规定以随机抽取方式提供虚拟道具时不得诱导用户直接投入法定货币 / 虚拟货币，若做「开箱抽玩具皮肤」须避开付费抽取结构。

**③ 实名与防沉迷（含过时口径标注）**
- **【实证·官方，现行依据】** 国家新闻出版署 国新出发〔2021〕14 号（2021-09-01 施行）<https://www.nppa.gov.cn/xxfb/tzgs/202108/t20210830_666285.html>：仅**周五、周六、周日和法定节假日每日 20–21 时**向未成年人提供 1 小时服务；所有网络游戏**必须接入 NPPA 网络游戏防沉迷实名验证系统**；**不得以任何形式（含游客体验模式）向未实名注册和登录的用户提供游戏服务**；「网络游戏企业含提供网络游戏服务的平台」。
- **【沿革记录，非现行口径】** 微信小游戏 2020-03-31 接入健康系统（中国青年网 / 南都 / 凤凰科技 / 新浪财经等多家报道）：平台统一实现实名认证、**开发者无需接入操作**；当时口径为每日 22 时至次日 8 时禁止、法定节假日 3 小时 / 其他 1.5 小时、8 岁以下禁付费、8–16 岁单次 50 元 / 月 200 元、16–18 岁单次 100 元 / 月 400 元。**这些时长口径已被 2021 年新规覆盖，本文不作为现行结论引用**；支付限额与"平台统一实现、开发者无需单独接入"的机制仍被广泛沿用，但**以提审当日平台要求为准**。网易《猫和老鼠官方手游》官网适龄提示页采用的已是 2021 新规口径，可作行业落地实例。
- **【推断】对商业轴 C 的连带影响**：不得有游客模式 → 首屏必须能承接实名弹窗后的即时进入（对应 §2 惯例 1）；未成年人在工作日基本不在线 → 实时匹配池缩小（已在 §3.1 ⑤ 说明）。

> **汇总判定**：**不构成硬阻断**。三项必做 = ①受击反馈保持非写实无害化（本项目已具备）②不做游客模式、依赖平台统一实名与防沉迷能力 ③有陌生人 PvP 就按 12+ 申报 + 敏感词过滤 + 举报入口 + 适龄提示设置并提交审核。

### 5.5 给立项书的三条硬输入

1. **首发范围按「免版号纯 IAA」定义**：前置 = 企业主体 + 微信认证 + ICP 备案 + 软著；**内购 / 混变需版号，列 Phase 2**，不要写进首发排期。政策处于变动期，一切以提审当日 mp 后台「资质审核」页为准（§3.4④）。
2. **排期第一项不是玩法，是两件前置**：①角色原创化设计 + 软著申请（周期长，同时是合规与维权证据）；②**8 人同屏低端 iOS 真机性能 spike**。这两件不过，后续联机与美术投入都会沉没（§3.3 / §4.1）。
3. **建议的立项验收阈值（内部参考，非官方标准）**：首屏 30 秒内给出完整「命中→击倒→播报→得分」闭环；单局 3–5 分钟、匹配 20 秒内必开局（Bot 补足）；≥5 个自愿激励视频点位且**真人局内不售卖战力**；低端机帧率 / 主包 ≤4M / 首屏加载达标；适龄提示按是否含陌生人社交决定 8+ 或 12+ 并提交审核。
