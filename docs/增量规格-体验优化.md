## 1. 分区伤害模型

### 1.1 部位倍率表（HP=100，单发基础 25 为基准，精度到整数）

| 部位 | `HitZone` | 倍率 | 单发伤害（**权威整数**） | 致死枪数 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 头部 | `head` | ×4.00 | **100** | **1** | 100 ≥ 100，满血一枪死（含手枪） |
| 胸部 | `chest` | ×1.00 | **25** | **4** | 4×25 = 100 |
| 腹部 | `belly` | ×0.76 | **19** | **6** | 6×19 = 114；5×19 = 95 < 100 |
| 手臂 | `arm` | ×0.76 | **19** | **6** | 同上（左右臂同值） |
| 腿部 | `leg` | ×0.72 | **18** | **6** | 6×18 = 108；5×18 = 90 < 100 |

**为什么伤害要存整数而不是 `Math.round(25 × 倍率)`：**`Player.hp` 是 Colyseus `uint8`，写入 `18.75` 会在序列化时被截断成 `18`，客户端 HUD 与服务端算的致死枪数可能差 1 发。所以**权威数据是 `ZONE_DAMAGE` 整数表**，倍率只是给人看的换算口径，代码里禁止用倍率算伤害。


### 1.2 判定几何：分段竖直圆柱（与第 2 节模型逐项对齐）

判定体 = **6 个与 Y 轴对齐的圆柱**（左右臂各 1 个），全部由同一份常量驱动客户端建模与物理身高。所有圆柱的轴在水平面上可偏离角色中心（`offsetRight`），计算时按 yaw 旋转到世界坐标：

```
right = ( cos(yaw), 0, -sin(yaw) )     // yaw=0 时朝 −Z，右手边为 +X
center = ( player.x + right.x * offsetRight, player.z + right.z * offsetRight )
```

```ts
/* packages/shared/src/index.ts —— 玩家判定体（本增量新增，必须与第 2 节模型尺寸表逐项相等） */

export interface HitCylinder {
  zone: HitZone;
  /** 圆柱轴相对角色中心、沿"右手方向"的水平偏移（米，左臂为负）。 */
  offsetRight: number;
  /** 圆柱下沿 / 上沿相对**脚底**的高度（米）。 */
  yMin: number;
  yMax: number;
  radius: number;
}

/**
 * 玩家判定体：6 个竖直圆柱，总高 0.02 → 1.80，与 PLAYER_HEIGHT 一致。
 * 站立时（y=0）各段世界高度：
 *   头 [1.54, 1.80]  胸 [1.14, 1.54]  腹 [0.90, 1.14]  臂 [0.98, 1.52]  腿 [0.02, 0.90]
 * 相邻段必须**首尾相接**（不留缝），缝隙会让垂直下压的子弹从两段之间漏判。
 */
export const PLAYER_HITBOXES: readonly HitCylinder[] = [
  { zone: "head",  offsetRight: 0,      yMin: 1.54, yMax: 1.80, radius: 0.14 },
  { zone: "chest", offsetRight: 0,      yMin: 1.14, yMax: 1.54, radius: 0.27 },
  { zone: "belly", offsetRight: 0,      yMin: 0.90, yMax: 1.14, radius: 0.25 },
  { zone: "arm",   offsetRight: 0.30,   yMin: 0.98, yMax: 1.52, radius: 0.10 },
  { zone: "arm",   offsetRight: -0.30,  yMin: 0.98, yMax: 1.52, radius: 0.10 },
  { zone: "leg",   offsetRight: 0,      yMin: 0.02, yMax: 0.90, radius: 0.20 },
];
```

几何自洽性（评审时逐条核对，不要凭感觉）：

- 头圆柱 r=0.14 ≥ 模型头球 r=0.13（判定比模型**宽 1cm**，网络延迟容错方向正确，宁可判中不判漏）。
- 胸 r=0.27 vs 模型胸盒半对角 `√(0.21² + 0.13²) = 0.247` → 宽 2.3cm，够容纳 15Hz 位置插值误差。
- 臂圆柱中心 ±0.30、r=0.10 → 覆盖 [0.20, 0.40]；模型上臂盒 x∈[0.245, 0.355] 完全被包住。
- 腿 r=0.20 vs 模型两条腿外沿 ±(0.095+0.075)=±0.17 → 余量 3cm；两腿合并成 1 个圆柱是为了少 1 次求交、且避免"从两腿之间穿过"的漏判。
- 大腿顶部（0.95）落在腹部区间（0.90–1.14）内，5cm 归腹部——这**不是错误**，腰部灰区由腹部 r=0.25 覆盖，不会漏判。
- 总高 1.80 = `PLAYER_HEIGHT` = 物理 `playerHeight` = 模型总高，四处同源。

### 1.3 判定算法（替换 `rayPlayerCylinder`）

对每个目标玩家、每个圆柱求交，取最小 t；t 差 ≤ 0.01m 时按 `ZONE_PRIORITY` 取优先部位：

```ts
/** 射线 vs 竖直圆柱（轴在 center，高度 yMin..yMax 为相对脚底，脚底为 baseY）。 */
export function rayVerticalCylinder(
  origin: Vec3, dir: Vec3, centerX: number, baseY: number, centerZ: number,
  yMin: number, yMax: number, radius: number, maxT: number,
): number | null {
  const ox = origin.x - centerX;
  const oz = origin.z - centerZ;
  const a = dir.x * dir.x + dir.z * dir.z;
  const c = ox * ox + oz * oz - radius * radius;
  if (a < 1e-9) {
    // 视线接近竖直：退化为"穿过圆盘"，与旧实现同样的兜底分支
    if (c > 0) return null;
    const yTo = dir.y > 0 ? baseY + yMin : baseY + yMax;
    const t = (yTo - origin.y) / dir.y;
    return t >= 0 && t <= maxT ? t : null;
  }
  const b = 2 * (ox * dir.x + oz * dir.z);
  const disc = b * b - 4 * a * c;
  if (disc < 0) return null;
  const sq = Math.sqrt(disc);
  for (const t of [(-b - sq) / (2 * a), (-b + sq) / (2 * a)]) {
    if (t < 0 || t > maxT) continue;
    const y = origin.y + dir.y * t;
    if (y >= baseY + yMin && y <= baseY + yMax) return t;
  }
  return null;
}
```

选定出口：`{ t, playerId, zone, point }`。`computeShot` 的返回值从 `ShotMessage` 扩展为下面的结构。**不要**给手雷、投掷物走这套判定（见 1.5）。

### 1.4 消息与状态字段划分

| 字段 | 去处 | 类型 | 理由 |
| --- | --- | --- | --- |
| `hitZone` | `SHOT` 广播（发给所有人）+ `DAMAGED`（发给受伤者） | `HitZone \| null` | 只有开枪者要显示"头部 -100"；旁观者可用它播爆头音 |
| `damage` | `SHOT` 广播 | `number` | 免去客户端反查表，保证 HUD 数字与服务端完全一致 |
| `hitPoint` | `SHOT` 广播 | `{x,y,z}` | 命中点火花/血雾位置（现有 `hit` 字段复用） |
| `headshot` | `KILL` 广播 | `boolean` | 击杀播报"爆头"标记与音效 |
| `hp` | 沿用状态同步（`Player.hp`） | `uint8` | 已同步，不重复进 SHOT |

### 1.5 明确排除项

- **投掷物不吃部位倍率。**手雷沿用 `apps/server/src/rooms/grenades.ts` 的 `explosionDamage`：中心 `maxDamage=100` → 边缘 `minDamage=20`，按爆炸点距离线性衰减，并且**对全身生效**（不区分头/腿）。理由：CS 的 HE 也是按距离衰减、不看部位；且手雷贴脸 100 伤害已经能秒人，再加头部 ×4 会变成无意义数值（400）。
- **本期不做护甲。**但预留字段，避免下期二次改协议：`Player.armor: uint8 = 0`（`@type("uint8")`）。下期加甲的规则写死为 `damage = Math.round(zoneDamage * armorPenetration)`，其中 AK `armorPenetration = 0.775`（社区口径）→ 满甲胸部 19 点、**5 枪死**，届时 1.1 节的表必须整表重算，不要局部改。
- **不做距离衰减。**CS 的 AK `rangeModifier=0.98`/500u 在 60m 射程内掉 3% 以内，对 4 枪/6 枪的整数致死枪数没有影响，本期只留 `distance` 字段。

### 1.6 单测断言（新增，防止三条线再次跑偏）

1. `ZONE_DAMAGE.head >= PLAYER_MAX_HP`、`Math.ceil(100/25) === 4`、`Math.ceil(100/19) === 6`、`Math.ceil(100/18) === 6`。
2. `PLAYER_HITBOXES` 的最小 `yMin` ≥ 0，最大 `yMax` === `PLAYER_HEIGHT`（1.8）。
3. 相邻段首尾相接：按 `yMin` 排序后 `abs(next.yMin - prev.yMax) < 1e-6`（臂段与躯干允许重叠）。
4. 从正前方 10m、与胸同高（y=1.6）水平射线打静止玩家 → `zone === "chest"`，`damage === 25`。
5. 同一射线抬高到 y=1.65（头部中心）→ `zone === "head"`，`damage === 100`。
6. 瞄准 y=0.4（小腿）→ `zone === "leg"`，`damage === 18`。

### 2.3 行走动画（与第一人称视模型同一套 bob 逻辑）

- 相位由**水平速度**推进（不新增网络字段，客户端用插值后的位置差算速度）：
  `bobPhase += horizontalSpeed * 1.5 * dt`（弧度/米 = 1.5）。
  5 m/s 走 → 7.5 rad/s ≈ **1.19 Hz**（一个完整步态周期含左右各一步）；8 m/s 冲刺 → 12 rad/s ≈ 1.91 Hz。
- 摆幅淡入复用视模型已有的 `advanceBobAmp`（τ = 120ms）：`amp = lerp(amp, speed > 0.5 ? 1 : 0, 1 - exp(-dt/0.12))`。
- 逐部件：

| 部件 | 旋转 | 公式 |
| --- | --- | --- |
| 左大腿 | `rotation.x` | `sin(bobPhase) * 0.55 * amp` |
| 右大腿 | `rotation.x` | `sin(bobPhase + π) * 0.55 * amp` |
| 左/右小腿 | `rotation.x` | `-0.6 * max(0, sin(bobPhase ∓ 0.6)) * amp`（负值 = 屈膝向后） |
| 左上臂 | `rotation.x` | `sin(bobPhase + π) * 0.32 * amp`（与左腿反相） |
| 右上臂 | `rotation.x` | `sin(bobPhase) * 0.14 * amp`（持枪手幅度更小，`*0.44` 阻尼） |
| 躯干 | `position.y` | `0.02 * sin(bobPhase * 2) * amp`（上下 2cm，双频） |
| 躯干 | `rotation.z` | `0.03 * sin(bobPhase) * amp`（左右轻晃） |

- `amp` 在离地（`vy` 变化超过 0.5 或 y > 0.05）时乘 0.5，与视模型的 `airDamp` 口径一致。
- 停走时相位**停止推进**（不归零），避免"停下一秒后再走，腿从 0 开始"的跳变。

**滚轮规则：**

1. `wheel` 事件累计 `deltaY`，按 **80ms 节流窗口**合并（一次快速滚两格只切一格，避免手抖连跳）。
2. `deltaY > 0` → 下一个槽；`deltaY < 0` → 上一个槽；**环形循环**（5 → 0）。
3. 跳过规则：投掷物数量为 0 跳过、P1 手枪未实现跳过（`enabled=false`）。若全部跳过（理论上不可能，刀恒有），停在当前槽不响应。
4. 数字键 `1`–`6` 直达，不做跳过判断（按到空槽 → 只播"咔"的空仓提示音，不切）。
5. 切枪期间（`now < switchEndAt`）**不能开火、不能挥刀、不能再切**（服务端与客户端都校验，服务端为准）。切到投掷物后可以立刻左键投掷（`switchEndAt` 到达后才允许投出，总延迟 250ms）。
6. 兼容旧操作（**保留，不删**）：`G`/`F`/`V` 改成"快捷投掷"——按下后自动 `weaponSlot = 对应槽` + 立即触发一次投掷请求（跳过抬手，`switchEndAt` 设为 `now`）。理由：毕设现场演示依赖单键，且回归测试 `throwables-room.test.ts` 直接调 `THROW` 消息不受影响。

## 4. 视角灵敏度

### 4.1 参数与换算

| 项 | 值 |
| --- | --- |
| 滑块范围 | **0.2 – 3.0** |
| 步进 | **0.05** |

```ts
export const VERTICAL_RATIO_DEFAULT = 1.0;
export const ADS_SENS_RATIO = 0.8;   // 本期不生效，下期开镜用

/** 非法值兜底：非有限数 / 越界 / 非数字 → 默认 1.0。 */
export function sanitizeSensitivity(raw: unknown): number {
  const value = typeof raw === "number" ? raw : Number(raw);
  if (!Number.isFinite(value)) return SENS_DEFAULT;
  return Math.min(SENS_MAX, Math.max(SENS_MIN, value));
}
```

- `pitch` 仍需 `MAX_PITCH = π/2 − 0.02` 钳制（现状 `game.ts:57` 保留）。
- 灵敏度**必须乘在原始 `movementX/movementY` 上**，不能乘在"每帧累加后的 delta"上等价替换——两者数学等价，但实现时乘法放在 `input.consumeLookDelta()` 之后、写 yaw 之前，才能保证拖滑块当帧生效。

### 5.3 随机策略（服务端 `nextSpawnPoint` 重写）

```ts
/* 伪代码，放 apps/server/src/rooms/spawn.ts（新建），便于单测 */
function pickSpawn(team: TeamId, players: Iterable<Player>, selfId: string, lastIndex: number): { point: SpawnPoint; index: number } {
  const candidates = TEAM_SPAWNS[team].map((point, index) => ({ point, index }));
  // 1. 排除被占用（同队其他存活玩家 1.2m 内）
  const free = candidates.filter(({ point }) =>
    [...players].every((p) => p.sessionId === selfId || !p.alive || Math.hypot(p.x - point.x, p.z - point.z) > 1.2),
  );
  // 2. 排除"敌人视线内"（复用 combat.ts 的 rayAabb：4 点 × ≤7 敌人 × 64 盒 ≈ 1.8k 次求交，可忽略）
  const safe = free.filter(({ point }) =>
    [...players].every((p) => p.sessionId === selfId || !p.alive
      || Math.hypot(p.x - point.x, p.z - point.z) > 12      // 12m 内才算威胁
      || rayAabb({ x: p.x, y: p.y + EYE_HEIGHT, z: p.z },
                 directionFromYawPitch(p.yaw, p.pitch), aabbOf(point), 40) !== null), // 有遮挡 = 安全
  );
  // 3. 三级回退
  const pool = safe.length > 0 ? safe : free.length > 0 ? free : candidates;
  // 4. 避免连续同一人同一个点：重抽最多 2 次
  let pick = pool[Math.floor(Math.random() * pool.length)];
  for (let i = 0; i < 2 && pool.length > 1 && pick.index === lastIndex; i++) {
    pick = pool[Math.floor(Math.random() * pool.length)];
  }
  // 5. 兜底：同队 4 点全被占（8 人房间里不会发生）→ 允许重叠，沿 +X 偏移 0.9m（见 5.4 实测坐标）
  return pick;
}
```

- `aabbOf(point)`：以 0.35 半径、高 1.8 构造的 AABB，用于"敌人是否能看到这个点"。
- 记录 `Player.lastSpawnIndex: uint8`（新增字段，只服务端用，不必 `@type`），用于第 4 步。
- 加入与重生**共用**该函数（替换 `fps-battle-room.ts:106-114` 的 `nextSpawnPoint` 与 `spawnCursor` 游标逻辑；游标字段可删）。

## 6. 弹道与命中反馈的一致性（反馈 ①）

### 6.1 三个根因（代码级）

1. **起点错**：`combat.ts:156` 的 `origin = { x, y + EYE_HEIGHT, z }` 是**眼睛**位置，客户端 `effects.addTracer(origin, hit)` 从眼睛画线。第一人称相机也在眼睛位置 → 弹道线从屏幕正中"凭空出现"往下延伸，而不是从右下方的枪口（`viewmodel.ts:30` 的枪根在相机 `(0.239, −0.228, −0.4)`）出现；贴近墙时视差更明显，玩家会觉得"子弹从身体里射出来"。
2. **方向陈旧**：`computeShot` 用的是**服务端最后收到的** `yaw/pitch`（`PLAYER_TRANSFORM_RATE_HZ = 15` → 最差 66ms 陈旧）。快速甩枪时，画面准星与服务端射线可差 1–3°，在 30m 外交战点（A 大道到 A 点）折算 **0.5–1.6m** 偏移 —— 这就是"我明明打中了"。
3. **准星撒谎**：客户端准星按 `spread`（`game.ts:64-67,550-551`）动态扩散，但**服务端完全没有扩散**，子弹永远沿正前方。准星张得越大，玩家越以为"这一枪会偏"，实际不偏；反之停火回弹时又以为"现在最准"。

### 6.2 弹道绘制规则

| 情况 | 画线起点 | 画线终点 | 说明 |
| --- | --- | --- | --- |
| `shooterId === selfId` | **本地枪口世界坐标**：`camera.localToWorld(枪口局部坐标 ≈ viewModel.getMuzzleWorldOffset() + holder.position)` | `message.hit` | 枪口坐标已含后坐/切枪/投掷位移，与画面火光完全重合 |
| 其他人 | `message.origin`（服务端算的枪口） | `message.hit` | 不信任本地推测，避免远端弹道漂移 |
| 命中玩家 | 同上 | `message.hit`，并在该点播**血雾**（红色粒子 0.25s）而非火花 | 现有 `effects.impact` 只播火花，打在人身上也冒火星，观感差 |
| 打空/打墙 | 同上 | `message.hit`，法线用 `-normalize(hit - origin)` | 现状保留 |

### 6.3 消息字段取舍（为什么三个都要发）

| 方案 | 问题 |
| --- | --- |
| 只发 `dir` | 客户端要自己算"到哪儿停下"（要自己跑 64 个 AABB + 所有玩家判定体）→ 客户端与服务器两套判定，正是本次要消灭的东西；且远端玩家算出的命中点与服务器不同步 |
| 只发 `hit` | 画线够用，但**命中点法线算不准**（火花朝向错），且无法在下期做"穿透/跳弹"表现 |
| 发 `origin + dir + hit` | **推荐**。额外开销 `dir` 3 个 float ≈ 12 字节/发，AK 满射速 6.7 发/秒 → 80 B/s/人，可忽略；同时 `dir` 让客户端能做"弹道拖尾方向"与未来的穿透射线 |

**服务端 `origin` 枪口偏移常量（与视模型姿态换算一致）：**

```ts
/* packages/shared/src/index.ts —— 视觉枪口相对眼睛的偏移（世界坐标系，按 yaw/pitch 旋转） */
export const MUZZLE_OFFSET = {
  right: 0.29,    // 相机 x = +0.239，枪口在枪身 −0.6 处，投影到右向 ≈ 0.29
  down: 0.20,     // 相机 y = −0.228，枪口略抬 0.03 → 0.20
  forward: 0.35,  // 枪根 −0.4 + 枪口 −0.6 = −1.0 是"视模型尺度"，实际世界尺度取 0.35（视模型是缩放过的假透视）
} as const;
```
`origin = eye + right * 0.29 + up * (−0.20) + dir * 0.35`。**判定射线仍从眼睛出发**（否则贴脸时会先打中自己的枪口模型/掩体边角），这一点必须写死并在代码注释里说明。

### 6.4 消除方向陈旧（两条，缺一不可）

1. `PLAYER_TRANSFORM_RATE_HZ` 15 → **30**（陈旧从 ≤66ms 降到 ≤33ms；上行带宽 30 msg/s × ~60B = 1.8KB/s/人，`MAX_MESSAGES_PER_SECOND = 30` 刚好卡满，**必须同时把该限流阈值提到 45**，否则上报被自己限流丢弃）。
2. `FIRE` 消息携带视角快照 `{ yaw, pitch }`（上行 +8B）。服务端规则：
   - 若 `|Δyaw| ≤ 3°` 且 `|Δpitch| ≤ 3°`（相对已存的最近一次 transform）→ **采用快照**（这就是"打哪中哪"的关键）；
   - 超出 3° → 丢弃快照、退回已存 `yaw/pitch`（防"瞬移视野爆头"作弊）；
   - 快照的 yaw/pitch 必须再走 `normalizeYaw` / `clampPitch`。

### 6.5 准星诚实性

- **本期 P0**：准星改为**静态**（固定 4 条 8px 线，间隔 `SPREAD_BASE = 3px`，不随射击/移动扩散）。理由是"没有扩散机制就别画扩散准星"——玩家的信任比一个装饰性动效重要。相机后坐（`RECOIL_PITCH = 0.016`）保留，仍然需要压枪，只是不再骗人。
- **下期 P1**：服务端按每发 `shotIndex` 做确定性扩散（`seed = hash(shooterId, shotIndex)`，角度偏移 ±`spreadRad`，第 1 发 0.2°、连射累积到 2.5°），把 `dir` 广播出来，客户端按**实际扩散半径**画准星（准星 = 真实弹道散布的投影）。此时才会重新出现动态准星。列第 8 节 #6。

## 7. 掩体穿模（反馈 ⑦）

### 7.1 客户端与服务端必须同口径的四件事

| 项 | 值 | 出处/要求 |
| --- | --- | --- |
| 玩家半径 | **0.35 m** | `DEFAULT_PHYSICS.playerRadius`，与 `PLAYER_HIT_RADIUS` 必须相等（单测断言） |
| 玩家高度 | **1.80 m** | `DEFAULT_PHYSICS.playerHeight` = `PLAYER_HEIGHT` |
| 障碍 AABB | 64 条，**客户端与服务端共用** `shared.obstacleColliders()` | 现状已共用（`map.ts:19` 重新导出），但服务端拿到了却没用 → 见 7.3 |
| 内缩/贴合容差 | `EPS = 0.001 m` | 推出目标 = 面 ∓ (r + EPS)，避免浮点误差导致下一帧又判重叠 → 抖动 |

**"玩家可站立的最近距离"公式：**

```
从 +X 侧贴近盒体：期望 x = box.minX − playerRadius = box.minX − 0.35
从 −X 侧贴近盒体：期望 x = box.maxX + 0.35
（Z 轴同理；墙角取两轴同时成立，即玩家中心在 (minX−0.35, minZ−0.35)）
```

### 7.2 穿模的四个真实根因（读代码得出，不是猜）

1. **垂直推出没有高度上限**（`player-physics.ts:171-186`）：`resolveBox` 在 `overlapY` 最小时把玩家"抬"到 `box.maxY`。玩家跳跃 apex = `jumpSpeed²/(2·gravity)` = `7.5²/(2·22)` = **1.278 m**，所以贴近任何 **≤1.278+0.35 的箱体**（1.4m 油桶、1.5m 车、1.6m 木箱！）都能被"顶"上去。这与 `shared` 注释里"高度必须落在 ≤1.15 可跳 / ≥1.4 必绕"的硬约束**正面冲突**——用户感觉到的"嵌进掩体"里有一半是"我明明跳不上 1.6m 的箱子，结果爬上去了"。
2. **单次遍历互相打架**：`for (const box of colliders) resolveBox(...)` 只跑一遍。若 A 盒把玩家推到 B 盒里，B 盒的推出结果**不会回头再检查 A**（贴着"箱-墙"夹角的点位尤其明显），表现为"人一半在箱子里"。
3. **垂直推出时机错**：任何时刻只要 `overlapY` 最小就抬升，而不是"只在下落且上一帧脚底在盒顶之上"才吸附 → 从侧面走进箱子底部时也会被抬高，跳过碰撞检测。
4. **服务端不校验障碍物**（`transform.ts`）：客户端上报什么位置就是什么位置。客户端一穿模，服务端与所有其他玩家就都看到"人嵌在箱子里"，而且该玩家还能在这个非法位置开枪打人。

### 7.3 规格要求（算法级，可直接实现）

```ts
/* 第 1 步：水平位移分片，防隧穿 */
const MAX_SUBSTEP = 0.25;                       // < playerRadius 0.35
const steps = Math.min(4, Math.max(1, Math.ceil(horizontalDistance / MAX_SUBSTEP)));

/* 第 2 步：每片内「先 X 后 Z」分轴解算，每轴各跑一遍迭代（最多 3 次） */
for (let i = 0; i < steps; i++) {
  x += dxPerStep;
  resolveAxisX(player, colliders);   // 只沿 X 推出，钳制到 box.maxX + r + EPS 或 box.minX − r − EPS
  z += dzPerStep;
  resolveAxisZ(player, colliders);
}

/* 第 3 步：垂直只做两件事 —— 落地吸附 + 台阶抬升，绝不"顶出盒体" */
// (a) 下落吸附：仅当 vy <= 0 且 prevFootY >= box.maxY − 0.02 且 footY < box.maxY 时，footY = box.maxY, vy = 0, grounded = true
// (b) 台阶抬升：仅当 grounded 且 盒顶 ≤ footY + STEP_HEIGHT(0.35) 且水平方向被该盒挡住时，footY = box.maxY（自动上台阶）
// (c) 其余情况：盒子对 Y 完全无作用（不抬不压）
```

- **X/Z 分轴**而不是"最小重叠轴"：分轴后每个轴的最优推出方向唯一（玩家在盒左就往左推），不会出现"该往左推却往上抬"。
- **必须保留的既有行为**：场地边界逐轴钳制（`MAP_BOUNDS`）、`y ≤ 0` 落地、跳跃（`jumpSpeed 7.5`）。
- `STEP_HEIGHT = 0.35`：小于所有"可跳"箱高（0.9/1.1），所以台阶逻辑只影响 0.35m 以下的地形缝隙；本项目地图里没有 0.35m 的台阶，等于"纯保守值"，不要指望它替代跳跃。

**验收用例（QA 逐条跑）：**

| # | 场景 | 期望 |

### 7.4 服务端校验（`transform.ts` 扩展）

```
1. 逐轴钳制 ±30、y ∈ [0, 10]         （现状保留）
2. 水平位移上限：dist > (sprintSpeed 8 * 1.25) * dtSinceLastReport + 0.30  → 丢弃本次上报（保留上次位置）
   其中 dtSinceLastReport = clamp(now - player.lastTransformAt, 16ms, 200ms)
3. 重叠校验：若玩家 AABB 与任一障碍 AABB 的重叠深度 > 0.10m → 对该盒做水平推出（最多 3 次迭代），再写状态
4. y 高度校验：若玩家 y > 0.05 且其下方 0.6m 内无盒体（既不在空中跳跃、也站不到东西上）
   → 按重力把 y 回落到最近的支撑面（盒顶或 0）。本期可只做 warn 日志 + 回落 0，避免误伤跳跃。
```

第 3 步是"别人看你不在墙里"的唯一保证；不做这一步，客户端无论怎么修都会有边角情况漏出来。

## 12. 第六轮：下蹲 / 倒地 / 投掷重做 / 弹道表现 / 新地图（2026-11-09）

### 12.1 下蹲（Ctrl / C）

| 项 | 值 | 说明 |
|---|---|---|
| 蹲姿眼高 | `CROUCH_EYE_HEIGHT = 1.02` | 站立 1.6 的 0.6375 倍，蹲 1.1m 箱后头顶刚好低于箱沿 |
| 判定体缩放 | `CROUCH_HEIGHT_SCALE = 0.63` | 只缩 `yMin/yMax`，头胸腹腿比例不变（不是重写一张表） |
| 移动速度 | `CROUCH_SPEED_SCALE = 0.42` | 蹲下**不能冲刺**；蹲走完全静音（脚步声判 `crouch`） |
| 网络 | `PlayerTransformMessage.crouch` + `Player.crouch` | 与位置同一包上报，只接受布尔 true（`"true"`/`1` 一律按站立） |

服务端因此有三处必须一起改，缺一处就会出现"看着蹲了却被打头"：
1. `computeShot` 的判定射线起点改用 `eyeHeightOf(shooter.crouch)`；
2. `rayPlayerHitboxes` 的每段圆柱上下沿乘 `heightScaleOf(target.crouch)`；
3. `respawn` 强制 `crouch = false`（否则蹲着死会白赚 37% 的判定体压缩）。

### 12.2 死亡倒地镜头

`DEATH_FALL_MS = 720` 内相机从眼高落到 0.28m，同时侧翻 1.18rad（约 68°）、俯角下压 0.42rad，
缓出曲线 `1 − (1−p)²`。倒地方向每局随机一次，倒地后仍可自由观察击杀者。
重生时 `deathProgress` 归零，不会带着上一局的翻滚角复活。

### 12.3 音效层（全部 WebAudio 合成，无外部采样）

新增：`headshotHit` / `fleshHit` / `bulletWhiz`（弹道擦身）/ `footstep` / `jump` / `land(intensity)`
/ `pinPull` / `grenadeBounce` / `boltAction` / `heartbeat`（低血量循环）/ `niceCheer`。

`niceCheer` 的人声用浏览器 `speechSynthesis` 念一句 "Nice!"，再叠两层人群噪声与上行三音；
TTS 不可用时自动退化为纯合成音。**不用任何主播/游戏采样**（版权）。

### 12.4 受击与击杀反馈分级

- 命中身体 → `hitmark`；命中头部 → `headshotHit`（更高更长）；
- 爆头**击杀** → 屏幕上方金色 `NICE!` 横幅（`#nice-banner`）+ 人声欢呼 + 轻微震屏；
- 受击按部位/伤害分两档：爆头或 ≥40 伤害走 `hurt(heavy)`（更长更低 + 耳鸣）；
- HP ≤ 35 启动心跳循环，死亡/重生立刻停。

### 12.5 投掷物（对标 CS2）

| 参数 | 旧 | 新 | 理由 |
|---|---|---|---|
| `THROW_SPEED` | 14 m/s | **21 m/s** | 45° 射程 v²/g：10.9m → 24.5m，能从中路扔进包点 |
| `THROW_MAX_PITCH` | 0.6 rad | **1.35 rad** | 0.6 时水平分量最小 0.826，任何角度都至少飞 22m，近投不可能 |
| 手雷半径 | 6m | **9.5m** | 高速下滑行 8–9m 才停，6m 会"看得见爆炸、打不到伤害" |
| 闪光半径 | 12m | **16m** | |
| 烟雾半径 | 5m | **7m** | |

**闪光视线遮挡**：`flashIntensity(center, radius, target, obstacles?)` 增加从爆炸点到眼睛的
线段求交，被掩体挡住直接返回 0（不是减半）——这就是「看见才致盲」。

**抛物线辅助**：手持投掷物时 `ThrowableSystem.updateAimArc` 用**同一个** `stepGrenadePhysics`
向前积分 260 步，每 0.1s 打一个点（`InstancedMesh`，40 点，单 draw call），
落地或静止即停。三种投掷物三种颜色。

### 12.6 弹道"像散弹枪"的修法

不是散布逻辑的问题（服务端扩散一直是权威的），而是**曳光太粗、太慢、太亮**：
半径 14mm → **6mm**、速度 260 → **340 m/s**、拖尾 2.4 → 3.6m、不透明度 0.92 → 0.62（加色混合）。
14mm 在 30m 处的投影接近 3px，四发并排就是一根光柱；6mm 只有 1px，才是 CS 里那条"细而亮"的线。
