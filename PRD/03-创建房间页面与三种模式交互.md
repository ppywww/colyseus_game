# 03｜创建房间页面：三种模式界面与交互规则

> 状态：待确认（根据已讨论的视觉稿与反馈整理）
> 适用平台：浏览器桌面端网页游戏
> 范围：创建房间后，不同游戏模式对应的房间界面、玩家展示与进入对局流程
> 原则：本文记录产品设计，不代表相关功能已在当前代码中实现；开发前需核对现有房间系统与服务端规则。

## 1. 总体设计

创建房间流程不再使用地图选择、房间名称、人数配置等参数弹窗作为本阶段设计重点。当前游戏只有一张地图，创建房间页面围绕模式选择和玩家状态展开。

三种模式共用同一套页面视觉语言，但根据所选模式显示不同的玩家区域和开始方式：

| 模式 | 页面类型 | 玩家展示 | 开始方式 |
|---|---|---|---|
| 1v1 | 双人等待大厅 | 两个玩家位置 | 房主点击“开始游戏” |
| 2v2 | 双队伍等待大厅 | 蓝队、红队各两个位置，共四个位置 | 房主点击“开始游戏” |
| 大乱斗 | 即时开始页面 | 不显示等待玩家席位 | 房主点击“开始游戏”后立即进入对局 |

### 1.1 共同布局

- **左侧角色展示区**：展示当前玩家在主菜单选择的角色，角色保持站立展示。初版不要求复杂动作或动效。
- **右侧操作区**：显示三种模式切换入口，以及当前模式专属的玩家信息或说明。
- **模式切换**：仅提供 1v1、2v2、大乱斗三种模式，不出现地图选择控件。
- **视觉风格**：沿用主菜单的房屋、院子、花园场景和原创卡通角色风格，保持桌面端宽屏布局。
- **返回入口**：提供返回操作，具体返回主菜单还是上一级页面按实际导航流程统一。

切换模式时，右侧区域应同步切换为对应布局，不应把三种模式的玩家席位同时堆叠显示。

## 2. 1v1 页面

### 2.1 页面结构

- 右侧显示模式选择，1v1 处于选中状态。
- 下方显示两个玩家席位：
  - 席位一：当前房主，显示房主头像、昵称和房主标识。
  - 席位二：空位时显示默认占位头像及“等待玩家”等提示；有玩家加入后显示该玩家头像和昵称。
- 页面底部显示房主专属的“开始游戏”按钮。

### 2.2 玩家加入与开始规则

1. 房主创建 1v1 房间后进入该页面。
2. 其他玩家加入后，自动填充第二个席位。
3. 玩家加入即视为准备完成，不显示“准备”按钮，也不要求玩家额外确认准备状态。
4. 只有房主显示并拥有“开始游戏”操作权限；普通玩家不显示开始游戏按钮。
5. 房主点击“开始游戏”后进入 1v1 对局。

### 2.3 状态表现

- 等待对手：第二个席位显示空位状态。
- 对手已加入：第二个席位显示真实玩家头像和昵称。
- 房间已满：不再显示可加入空位；是否允许其他玩家加入由房间系统限制。

## 3. 2v2 页面

### 3.1 页面结构

右侧玩家区域划分为两个清晰的阵营：

- **蓝队**：两个玩家席位。
- **红队**：两个玩家席位。

总计四个玩家席位。每个席位显示玩家头像和昵称；空位显示默认占位头像及等待提示。房主头像旁显示房主标识。

页面底部显示房主专属的“开始游戏”按钮。房主和普通玩家均可在开局前切换自己的队伍。

### 3.2 切换队伍交互（重点）

每位已加入房间的玩家，在自己的玩家席位附近拥有一个明确的**切换队伍按钮**（可使用双向箭头或交换图标）。

点击后：

1. 将当前玩家从所在阵营移动到另一阵营的空余席位。
2. 玩家头像与昵称以平滑、明确的位移动画移动到另一队伍区域。
3. 移动完成后，玩家所属队伍状态更新；头像、昵称和队伍归属保持一致。
4. 切换过程应快速，不阻塞其他操作；切换按钮在操作处理中短暂防止重复触发。
5. 开始游戏前允许玩家再次切换队伍，直到房主开始对局或房间状态不再允许变更。

**队伍席位限制建议：**每队最多两人。若目标队伍没有空位，切换按钮应不可用或给出“对方队伍已满”的清晰提示，不应覆盖已有玩家。若后续希望支持两队满员时互换位置，可再补充双人交换规则；当前初稿不默认实现该规则。

### 3.3 玩家加入与开始规则

1. 玩家加入房间后，进入蓝队或红队的空余席位。
2. 玩家加入即视为准备完成，不显示“准备”按钮。
3. 玩家可通过自己的切换队伍按钮，在开局前更换阵营。
4. 只有房主显示“开始游戏”按钮，普通玩家不显示该按钮。
5. 房主点击“开始游戏”后进入 2v2 对局。

### 3.4 状态表现

- 蓝队、红队分别显示当前人数，例如“蓝队 1/2”“红队 1/2”。
- 空席位始终清晰可见，便于玩家理解还可加入多少人。
- 队伍切换后，双方阵营人数立即更新。
- 房间满员时四个席位均显示玩家信息。

## 4. 大乱斗页面

### 4.1 页面结构

- 左侧继续展示当前玩家在主菜单选择的角色。
- 右侧显示模式选择，大乱斗处于选中状态。
- 不显示 1v1 / 2v2 式的等待玩家席位，也不显示队伍分组。
- 显示简短说明，例如“无需等待其他玩家，点击开始即可进入游戏”。
- 页面底部显示醒目的“开始游戏”按钮。

### 4.2 进入对局规则

1. 房主选择大乱斗后，不需要等待其他玩家加入。
2. 房主点击“开始游戏”后，立即进入大乱斗游戏画面。
3. 其他玩家可以从房间列表中加入正在进行的大乱斗房间；加入后直接进入该场游戏画面，不进入等待大厅，也不需要点击准备。
4. 大乱斗房间应支持对局进行中加入（中途加入）。加入资格、人数上限及对局结束后的处理，以实际游戏规则为准。

## 5. 角色展示与选择结果

- 左侧展示的角色必须与玩家在主菜单选择的角色一致。
- 本页面初版只要求角色站立展示，不把角色待机动作或复杂交互动画作为上线前置条件。
- 进入对局时沿用当前玩家最终选择的角色。
- 本文不改变主菜单已确认的角色选择交互规则。

## 6. 权限与状态规则汇总

| 操作 / 状态 | 房主 | 普通玩家 |
|---|---|---|
| 查看当前模式 | 是 | 是 |
| 查看玩家席位 | 是 | 是 |
| 1v1 / 2v2 自动视为准备完成 | 是 | 是 |
| 1v1 / 2v2 切换队伍 | 不适用 | 仅 2v2 适用 |
| 2v2 切换队伍 | 是 | 是 |
| 显示“开始游戏”按钮（1v1 / 2v2） | 是 | 否 |
| 大乱斗点击开始后立即进入对局 | 是 | 不需要等待房主大厅流程 |
| 加入进行中的大乱斗并直接进入对局 | 不适用 | 是 |

> 注：大乱斗的房主开始游戏与其他玩家中途加入，是两种不同入口：房主从创建页面开始对局；其他玩家从房间列表加入正在进行的对局。

## 7. 验收标准

### 1v1
- [ ] 页面仅展示两个玩家席位。
- [ ] 房主和加入玩家的头像、昵称正确显示。
- [ ] 加入玩家后自动视为准备完成，没有准备按钮。
- [ ] 只有房主能看到开始游戏按钮。

### 2v2
- [ ] 页面展示蓝队和红队，每队两个席位。
- [ ] 玩家头像、昵称和房主标识显示正确。
- [ ] 玩家可在开局前通过切换队伍按钮切换阵营。
- [ ] 切换后头像和昵称移动到另一队伍的空席位，队伍人数同步更新。
- [ ] 目标队伍满员时不会覆盖其他玩家。
- [ ] 只有房主能看到开始游戏按钮。

### 大乱斗
- [ ] 页面不显示等待玩家席位或队伍分组。
- [ ] 房主点击开始游戏后直接进入对局。
- [ ] 其他玩家从房间列表加入正在进行的房间后直接进入对局，不进入等待大厅。

### 通用
- [ ] 三种模式切换时，页面布局和内容正确变化。
- [ ] 左侧始终展示当前玩家已选择的角色。
- [ ] 页面不出现地图选择控件。
- [ ] 不修改游戏代码，直至本设计文档确认并进入开发阶段。
