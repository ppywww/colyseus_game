# 游戏 PRD（产品需求文档）

本目录是《Colyseus Game》的产品需求文档入口。文档按“整体流程 → 独立页面”的方式组织，避免把全局玩法流程和单个页面的详细设计混写。

## 文档结构

| 编号 | 文档 | 职责 |
|---|---|---|
| 01 | [整体游戏流程与交互逻辑](./01-整体游戏流程与交互逻辑.md) | 描述从打开游戏、主菜单、创建 / 加入房间、进入对局到结束对局的完整流程，以及页面之间的跳转关系 |
| 02 | [主菜单页面 PRD](./02-主菜单页面PRD.md) | 只描述主菜单的布局、视觉、功能入口、角色选择和交互细节 |
| 03 | [创建房间页面与三种模式交互](./03-创建房间页面与三种模式交互.md) | 只描述创建房间后的 1v1、2v2、大乱斗页面差异、玩家席位、队伍切换和开局规则 |
| 04 | [加入房间页面与加入流程设计](./04-加入房间页面与加入流程设计.md) | 只描述房间列表、搜索刷新、房间详情、加入条件和加入后的流转 |
| 05 | [游戏内设置页面 PRD](./05-游戏内设置页面PRD.md) | 只描述鼠标灵敏度、准星、声音 / 音效，以及主菜单和对局中的设置入口 |

## 阅读方式

- 想了解整个游戏怎么玩、页面如何串联：先看 **01**。
- 想了解某一个页面的具体设计：直接看对应的 **02—05**。
- 01 负责全局流程，不重复展开页面控件细节；02—05 负责各自页面的完整需求。
- 页面文档中的具体规则如有更新，应同步检查 01 中对应的流程描述。

## 工作原则

1. 先讨论并形成 PRD，再根据确认结果修改游戏代码。
2. 未经确认的建议明确标注为待确认，不当作已经实现或最终确定的规则。
3. PRD 记录产品目标、页面行为、异常状态和验收标准；技术实现以实际代码和服务端能力为准。
4. 当前阶段只整理产品文档，不因本次文档调整修改游戏代码。

## 状态约定

- **待讨论**：尚未形成方案。
- **待确认**：已有建议方案，等待确认。
- **已确认**：已得到确认，可作为后续设计与开发依据。
