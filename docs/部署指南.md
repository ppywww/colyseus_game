# 部署指南（云服务器单机部署）

面向本科毕设演示场景：一台 1.6G 内存的 Ubuntu 云服务器，前端静态文件 + Colyseus 服务端同机部署，只占用 **80 端口**，不改云安全组。

## 一、目标架构

```
浏览器 ──HTTP──▶ nginx :80 ──┬─ /            → /var/www/fps  （Vite 构建产物）
                            └─ /fps-ws/     → 127.0.0.1:2567（Colyseus）
                                                   ▲
                                    matchmake 走 HTTP POST，房间走 WebSocket 升级
```

要点：

- **单端口单源**：页面与 WebSocket 同源，客户端自动推导 `ws(s)://<当前域名>/fps-ws`，换域名/加 HTTPS 都不需要重新构建前端；
- **服务端只监听 127.0.0.1**，不对公网暴露 2567，云安全组无需新增放行规则；
- nginx 用 `server_name <IP>` 精确匹配，不影响同机已有的其他站点（原有 `default_server` 继续服务域名访问）；
- 前端 `base` 为 `/`，构建产物直接铺在站点根目录。

## 二、一键部署

```bash
pnpm deploy            # 等价于 bash scripts/deploy-remote.sh
```

脚本做的事（幂等，可反复重跑）：

1. 本地 `pnpm build`（**构建一律在本地做**，目标机内存小，跑 tsc/vite 容易把系统拖垮）；
2. 打包源码 + 构建产物上传（排除 `node_modules` / `.git` / `.workbuddy`）；
3. 服务器侧：解包 → 必要时安装 Node 24（官方二进制包解压到 `/opt/node-v24`，**不经过 apt/dpkg**）→ 安装 pnpm → 只装服务端生产依赖；
4. 写 systemd 单元 `/etc/systemd/system/fps-server.service` 并启动（`Restart=always`、`MemoryMax=640M`，防止和 nginx 互抢内存）；
5. `rsync` 发布前端到 `/var/www/fps`；
6. 写 nginx 站点 `/etc/nginx/conf.d/fps.conf` 并 reload；
7. 健康检查：首页必须 200，`matchmake/joinOrCreate/<room>` 必须返回 `roomId`。

### 可覆盖的环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DEPLOY_HOST` | `my-aliyun` | `~/.ssh/config` 里的主机别名，或 `root@1.2.3.4` |
| `DEPLOY_DIR` | `/root/Projects/colyseus-fps` | 服务器上的代码目录 |
| `DEPLOY_WEB_ROOT` | `/var/www/fps` | nginx 静态根目录 |
| `DEPLOY_SERVER_NAME` | 从 ssh 配置解析出的 IP | nginx `server_name`，绑定域名时改这个 |
| `NODE_VERSION` | `24.20.0` | 服务器上的 Node 版本 |
| `SERVER_PORT` | `2567` | 服务端本地端口 |

例如绑定域名：

```bash
DEPLOY_SERVER_NAME=game.example.com pnpm deploy
```

## 三、日常运维

```bash
ssh my-aliyun systemctl status fps-server     # 服务状态
ssh my-aliyun journalctl -u fps-server -f     # 实时日志（stdout/stderr 同时落 logs/server.log）
ssh my-aliyun systemctl restart fps-server    # 重启
```

## 四、踩过的坑（务必保留这些约束）

1. **不要在目标机上装 apt 包**。首次部署尝试用 `apt install nodejs`，在 1.6G 内存 + 2 核的机器上把 dpkg 拖死，ssh 直接失联，只能控制台重启。改用官方二进制包后一条命令装完。
2. **不要顺手加 swap 再装包**。当时 `fallocate 2G` + apt 同时跑，内存被挤到换页，HTTP 响应从 0.3s 变成 9s。现在 swap 已常驻（2G），但真正该避免的是在机器上跑重负载。
3. **WebSocket 反代必须带 `Upgrade` / `Connection` 头且 `proxy_http_version 1.1`**，否则 Colyseus 握手 400。`/fps-ws/` 的 `proxy_pass` 末尾带 `/`，用来剥掉前缀——Colyseus 服务端只认 `/<processId>/<roomId>` 这类两段路径。
4. **`proxy_read_timeout` 要给到小时级**，否则空闲房间会被 nginx 每 60s 掐一次连接。

## 五、验证清单

```bash
curl -o /dev/null -w '%{http_code}\n' http://<IP>/                     # 期望 200
curl -s -X POST -H 'Content-Type: application/json' -d '{}' \
  http://<IP>/fps-ws/matchmake/joinOrCreate/fps_battle                 # 期望返回 roomId
```

浏览器打开 `http://<IP>/`，开两个窗口分别输入玩家名进入战场，验证：能互相看到、互相射击掉血、手雷/闪光/烟雾、换弹。
