# 02｜对局前后续页面与游戏内设置界面

> 状态：设计方案初稿  
> 适用平台：浏览器桌面端网页游戏  
> 说明：主菜单不在本文重复设计；本文件聚焦“创建房间”“加入房间”及进入对局后的游戏内设置。页面视觉细节由设计先行决定，后续通过效果图继续调整。

## 1. 页面流程总览

主菜单沿用此前已讨论的版本，不再重新生成主菜单效果图。

页面流程：
1. 主菜单点击“创建房间” → 创建房间 / 房间等待页面。
2. 主菜单点击“加入房间” → 房间列表页面 → 选择房间并加入。
3. 创建者与加入者最终进入同一个房间等待空间；满足开始条件后进入对局。
4. 对局过程中可打开游戏内设置面板；准星、鼠标灵敏度等战斗相关设置应在游戏过程中也能快速调整。

## 2. 创建房间页面

### 2.1 页面目标
让玩家快速创建一个可供好友或其他玩家加入的房间，并清楚知道房间是否创建成功、当前房间信息和等待状态。

### 2.2 建议布局
- 页面采用桌面端宽屏布局，沿用主菜单的卡通世界观、色彩体系、字体和控件质感。
- 主区域展示房间创建信息与房间状态；背景可继续使用房屋、院子或室内空间的延伸场景，但降低背景细节对文字的干扰。
- 明确显示房间名称或房间号、当前人数 / 最大人数、公开或私密状态（若项目支持）。
- 主要操作按钮：创建 / 确认创建、复制房间号或邀请信息、返回。
- 创建成功后转为房间等待状态，展示已加入玩家与等待开始状态。
- 不擅自增加复杂的匹配参数；房间规则和可配置项以项目实际支持能力为准。

### 2.3 状态与反馈
- 创建中：按钮显示加载状态，避免重复提交。
- 创建成功：突出显示房间号及复制操作。
- 创建失败：用清晰、可理解的提示说明原因，并允许重试。
- 等待中：明确显示当前人数与开始条件。

## 3. 加入房间页面

### 3.1 页面目标
让玩家快速浏览可加入的房间，理解每个房间是否可加入，并完成加入操作。

### 3.2 建议布局
- 页面主体采用清晰的房间列表 / 卡片列表，不使用拥挤的小字表格。
- 每个房间条目优先显示：房间名称或编号、人数、状态、地图或模式（仅当项目确实提供这些信息时）。
- 提供刷新入口；如果房间较多，再考虑搜索或筛选，不把复杂筛选作为第一版必需功能。
- 每个可加入房间有明确的“加入”操作。
- 页面保留返回主菜单入口。

### 3.3 状态与反馈
- 加载中：显示列表加载状态。
- 空列表：说明当前没有可加入房间，并提供刷新操作。
- 房间已满 / 已关闭：显示不可加入状态，不允许误点。
- 加入成功：进入统一的房间等待页面。
- 加入失败：说明原因并允许返回列表重试。

## 4. 统一房间等待页面

创建房间与加入房间最终汇入同一个等待页面，避免维护两套重复的等待体验。

建议展示：
- 房间号 / 房间信息；
- 当前玩家列表与人数；
- 房主标识（若项目支持房主概念）；
- 等待开始状态；
- 离开房间操作；
- 房主可见的开始游戏操作（仅在项目规则允许时显示）。

玩家列表应突出角色头像或角色形象，但不展示经验、等级等成长系统信息。

## 5. 游戏内设置面板

### 5.1 设计原则
- 准星与鼠标灵敏度属于对局操作设置，必须能在游戏过程中打开和调整。
- 游戏内设置入口应易于找到，但不能遮挡主要战斗视野。
- 设置面板建议采用半透明、紧凑的桌面端浮层；打开时游戏是否暂停由实际多人对局规则决定，不默认暂停其他玩家的游戏。
- 调整后应能即时预览效果；提供恢复默认值的方式。

### 5.2 设置分类与建议控件

**鼠标**
- 鼠标灵敏度：滑块调节，旁边显示当前数值。
- 可选：反转 Y 轴（如项目输入系统支持）。

**准星**
- 准星样式：提供若干清晰的预设样式。
- 准星颜色：提供颜色选择和高对比度预设。
- 准星大小 / 长度；
- 准星粗细；
- 中心间距；
- 透明度；
- 中心点开关（若实现成本合理）。
- 面板中设置实时预览区域，避免玩家只能凭参数猜效果。

**声音**
- 主音量；
- 音效音量；
- 如项目存在独立音乐轨道，再增加音乐音量；若没有则不显示无效选项。

**操作**
- 应用 / 保存；
- 恢复默认；
- 关闭设置。

以上为建议设计项，不代表所有参数都已在现有代码中实现；后续开发前需核对游戏实际支持能力。

## 6. 视觉一致性

- 后续页面沿用主菜单已选定的原创卡通美术方向，不重新引入另一套视觉风格。
- 使用统一的按钮形状、边框、字体层级、图标线条、阴影和状态色。
- 主要操作按钮突出，次要操作弱化；危险操作（如离开房间）需要明确区分。
- 页面背景可以变化，但 UI 组件应保持一致。
- 所有页面按浏览器桌面端设计，优先适配常见 16:9 宽屏，同时兼顾窗口缩放。

## 7. 后续页面效果图顺序

建议按以下顺序制作视觉预览：
1. 创建房间 / 房间等待页面；
2. 加入房间列表页面；
3. 游戏内设置面板（重点展示准星实时预览、鼠标灵敏度和音量控制）。

先确认页面结构和视觉层级，再补充具体字段与交互细节。本阶段只更新设计文档和视觉方案，不修改游戏代码。
