# 客户端技术选型与资源加载架构

> 状态：当前技术基线依据仓库代码整理；资源预加载、缓存和性能优化部分属于建议方案，需结合实际实现与测试逐步确认。

## 1. 目标与选型原则

游戏运行在桌面浏览器，采用横屏 3D 第一人称射击体验。客户端技术方案以现有 **TypeScript + Three.js + Vite** 为基础，不在没有明确收益的情况下整体更换渲染引擎。

客户端需要兼顾：
- 画面表现与稳定帧率。
- 鼠标、键盘等桌面输入体验。
- 多人实时状态的平滑呈现。
- 首次打开速度、对局前资源准备和游戏过程中的网络占用。
- 不同浏览器与设备性能的适配。

## 4. 渲染与性能方向

### 4.1 渲染方案

继续使用 Three.js。画面目标为精致、清晰且适合浏览器运行，不以单纯堆叠高精度模型和特效为目标。

### 4.2 性能优化方向（待实现情况逐项核对）

- 控制模型面数、材质数量和纹理尺寸。
- 合理复用材质、几何体和纹理，减少重复创建。
- 根据距离和画面占比使用 LOD。
- 对粒子、烟雾、弹道和其他特效设置数量上限。
- 控制阴影、后处理和实时光源的成本。
- 对资源及时释放，避免场景切换后 GPU 显存持续增长。
- 以目标设备实测帧率、内存和加载时间作为优化依据。

## 5. 游戏资源加载与缓存系统

### 5.1 设计目标

避免玩家进入对局后才临时下载大量模型、贴图、地图、动画和音效，减少加载过程对游戏体验的影响；同时避免首次打开页面就强制下载所有游戏资源。

### 5.2 推荐加载流程

1. **启动阶段：** 加载运行游戏必需的 JS、基础 UI、字体和主菜单必要资源。
2. **后台预加载阶段：** 在不阻塞主菜单交互的情况下，预加载常用角色、基础音效和高概率使用资源。
3. **模式 / 地图确定后：** 根据本局地图、角色和装备生成资源清单。
4. **进入对局前：** 检查本地缓存，下载缺失或版本不匹配的资源；必要时展示加载进度。
5. **开局条件：** 关键资源准备完成后再允许进入正式对局，避免玩家出生后出现模型缺失或贴图突然弹出。
6. **对局过程中：** 尽量只读取已缓存资源；确实需要动态资源时采用低优先级异步加载，不阻塞主线程和渲染循环。
7. **版本更新：** 通过带版本或内容哈希的资源 URL 更新缓存，避免旧缓存与新程序不匹配。

### 5.3 技术分工建议

| 技术 / 机制 | 建议职责 | 当前状态 |
|---|---|---|
| Vite 构建产物 | 代码拆分、静态资源引用与构建版本管理 | Vite 已使用；具体策略待核对 |
| HTTP(S) 静态资源服务 | 提供模型、贴图、音频等文件 | 部署方式待确认 |
| CDN | 靠近玩家分发静态资源，降低跨区域下载延迟 | 建议评估，尚未确认 |
| 浏览器 HTTP Cache | 缓存带正确缓存头的静态文件 | 浏览器能力可用；服务端配置待确认 |
| Service Worker | 管理预缓存、运行时缓存和更新 | 建议评估，尚未确认 |
| IndexedDB | 需要显式管理的较大资源元数据或离线数据 | 按需求评估，不默认必须使用 |
| 资源清单（manifest） | 描述本局所需资源、版本、大小和依赖 | 建议设计 |

资源下载应使用 HTTP(S)，实时房间消息只传必要的游戏状态，不通过 Colyseus WebSocket 发送大体积资源文件。

### 5.4 缓存与更新原则

- 资源 URL 或清单必须具备版本标识，内容变化时能可靠更新。
- 可长期缓存带内容哈希的静态资源；入口 HTML 和资源清单应采用适合更新检查的缓存策略。
- 缓存空间有限，需考虑过期清理和旧版本回收。
- 缓存失败、浏览器禁用存储或空间不足时，应能退回在线下载。
- 不应在未获用户同意的情况下无限占用本地存储。
- 预加载任务应可取消、限速或降优先级，避免影响当前游戏操作。

## 6. 网络通信与画面呈现

- 使用 `colyseus.js` 连接现有 Colyseus 服务端。
- 网络状态更新与渲染帧循环解耦，避免收到网络消息就执行昂贵的同步渲染。
- 远端玩家使用插值平滑状态变化；预测和纠正策略需与服务端权威规则协同。
- 对断线、重连、延迟升高和房间结束提供明确 UI 状态。
- 只同步必要字段，避免重复传输可由客户端本地计算的纯表现数据。

## 7. 浏览器兼容与降级

- 首期目标为桌面浏览器，不以移动端触控为首要适配目标。
- 对 WebGL 能力、显存和关键浏览器 API 做启动检测。
- 提供画质档位或可调选项，按设备能力调整阴影、特效、渲染分辨率等。
- 资源加载失败时显示可理解的错误与重试入口，不应无限停留在加载状态。

## 8. 后续待确认事项

- 首期支持的浏览器及最低设备配置。
- 目标帧率与画质档位。
- 资源总量、单张地图资源体积和首屏预算。
- 是否采用 CDN、部署区域和静态资源托管方式。
- Service Worker 的缓存范围、更新与回滚策略。
- 是否需要 IndexedDB 管理离线资源。
- 地图 / 模式 / 角色资源清单如何生成。
- 对局开始前的资源就绪判定与超时处理。

## 9. 性能与加载验收方向

建议至少记录并测试：
- 首次打开到主菜单可交互的时间。
- 首次进入指定地图的资源下载量和加载时间。
- 第二次进入相同地图时的缓存命中情况。
- 对局中是否发生大体积资源请求。
- 不同网络条件下的加载失败与重试体验。
- 目标设备上的平均帧率、帧时间、内存和显存占用。

具体指标数值应在选定测试设备和网络条件后共同确定，不在缺少基准测试时臆定。
