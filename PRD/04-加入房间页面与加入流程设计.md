# 04｜加入房间页面与加入流程设计

> 状态：待确认（文字方案初稿）
> 适用平台：浏览器桌面端网页游戏
> 范围：玩家从主菜单进入房间列表、查看房间信息并加入房间
> 原则：本文只记录产品设计，不代表功能已在代码中实现；不修改游戏代码。

## 1. 设计目标

加入房间页面应让玩家快速找到可加入的公开房间，并清楚了解房间模式、人数和当前状态。页面沿用主菜单的视觉语言，不再重复设计角色选择流程。

## 2. 页面总体布局

采用桌面浏览器横屏布局，分为左右两个主要区域：

- **左侧角色展示区**：展示玩家在主菜单选中的角色及玩家昵称。角色保持较大比例，作为页面的视觉锚点；不要求初版加入复杂动作。
- **右侧房间浏览区**：展示可加入的房间列表，是页面主要操作区域。
- **页面顶部**：显示“加入房间”标题，以及搜索和刷新操作。
- **返回入口**：允许玩家返回主菜单。

页面应有清晰的层级、足够的留白和明确的选中状态，避免列表信息拥挤。

## 3. 房间列表

每个房间条目建议展示以下信息：

| 信息 | 展示内容 |
|---|---|
| 房间名称 | 房主设置或系统生成的房间名称；若当前系统没有自定义名称，则显示可读的默认名称 |
| 游戏模式 | 1v1、2v2 或大乱斗标签 |
| 玩家人数 | 当前人数 / 该模式可容纳人数 |
| 房间状态 | 等待中、进行中等状态 |
| 操作 | 可加入时显示“加入”入口；不可加入时显示原因或禁用状态 |

列表默认优先展示可加入的房间。满员或已结束的房间不应被误认为可加入房间。

### 3.1 搜索与刷新

- 搜索框用于按房间名称查找房间。
- 刷新按钮用于重新获取房间列表。
- 刷新过程中应有轻量加载反馈，避免玩家误以为按钮没有响应。
- 搜索无结果时显示明确的空状态提示，并允许清除搜索条件。
- 房间列表应在有新房间创建、房间人数变化或房间状态变化时及时更新；具体采用实时推送还是定时刷新由技术实现决定。

## 4. 房间详情与加入操作

建议采用“选择房间后查看详情，再确认加入”的交互，避免玩家误点列表条目就直接进入房间。

选中房间后，在右侧列表附近展示详情区域（可采用列表右侧详情面板，或列表上方/下方的展开区域）。详情建议包括：

- 房间名称与模式。
- 当前玩家人数及剩余空位。
- 已加入玩家的头像和昵称。
- 房间状态。
- “加入房间”按钮。

当前游戏只有一张地图，因此不需要地图选择。若详情中展示地图信息，只作为固定地图的简要说明或预览，不提供切换控件。

点击“加入房间”后，根据房间模式执行对应流程：

### 4.1 加入 1v1 房间

- 仅当房间仍有空位且处于等待状态时允许加入。
- 成功加入后进入该房间的 1v1 等待大厅。
- 玩家加入即视为准备完成，不显示准备按钮。
- 房间满员或已开始时，应阻止加入并提示玩家刷新列表或选择其他房间。

### 4.2 加入 2v2 房间

- 仅当房间仍有空位且处于等待状态时允许加入。
- 成功加入后进入该房间的 2v2 等待大厅。
- 玩家进入后分配到一个可用队伍席位；具体默认分队策略需与房间系统规则一致。
- 玩家可以按照第 03 份 PRD 的规则，在开局前使用切换队伍按钮更换阵营。
- 玩家加入即视为准备完成，不显示准备按钮。

### 4.3 加入大乱斗房间

- 房间列表应能区分等待开始与正在进行中的大乱斗房间。
- 加入正在进行的大乱斗房间后，玩家直接进入该场对局，不进入等待大厅，也不需要点击准备。
- 仅当房间允许中途加入且未达到人数上限时，才显示可加入状态。
- 若房间不允许加入或已经满员，应显示不可加入状态及清晰原因。

## 5. 异常与空状态

- **暂无房间**：显示友好的空状态说明，并提供刷新操作。
- **搜索无结果**：提示没有找到匹配房间，并允许清空搜索。
- **房间已满 / 已开始 / 已关闭**：加入前再次校验房间状态；若状态已变化，提示玩家并刷新列表。
- **网络或列表加载失败**：显示错误提示和重试入口，不应清空玩家当前角色选择。
- **加入失败**：保留当前页面与搜索状态，提示失败原因，允许重试。

## 6. 与其他页面的关系

- 主菜单的“加入房间”按钮进入本文定义的房间列表页面。
- 左侧展示沿用主菜单已经选择的角色，不在加入房间页面重新选角。
- 加入 1v1 或 2v2 后，进入对应的等待大厅；其玩家席位、房主权限和开始规则以第 03 份《创建房间页面与三种模式交互》为准。
- 加入正在进行的大乱斗房间后，直接进入对局。
- 本文不重新定义创建房间流程，也不修改第 03 份文档。

## 7. 验收标准

- [ ] 加入房间页面与创建房间页面使用独立的页面文档和入口流程。
- [ ] 左侧正确展示当前玩家已选择的角色。
- [ ] 房间列表展示房间名称、模式、人数和状态。
- [ ] 支持按房间名称搜索和手动刷新。
- [ ] 选择房间后能够查看详情，并明确看到加入操作。
- [ ] 1v1、2v2 等待房间加入后进入对应等待大厅。
- [ ] 2v2 玩家进入后可按第 03 份 PRD 的规则切换队伍。
- [ ] 正在进行且允许中途加入的大乱斗房间，加入后直接进入对局。
- [ ] 房间满员、已开始、已关闭等状态不会被错误地显示为可加入。
- [ ] 列表为空、搜索无结果、加载失败和加入失败均有明确反馈。

## 8. 待确认事项

以下内容先按易用性给出建议，后续可根据你的反馈调整：

1. **房间详情的呈现方式**：建议选中列表条目后，在右侧打开详情面板；也可以改为点击列表条目直接加入。
2. **搜索范围**：初版建议只按房间名称搜索；是否增加模式筛选，后续再决定。
3. **房间名称来源**：需要核对现有系统是否支持房主自定义名称；若不支持，使用系统生成名称。
4. **大乱斗中途加入规则**：最大人数、是否允许任何时间加入，以及临近对局结束时是否限制加入，需要结合实际对局规则确定。
5. **列表更新机制**：实时更新或定时刷新由技术实现结合现有 Colyseus 房间列表能力决定。
